# Revia のコンセプト

このアプリが何を解決し、何をしないかを書く。**変わりにくいもの**を置く場所で、MVP の範囲や画面の仕様は [requirements.md](requirements.md) にある。

決める過程は Issue #5 に残っている。

## 解決したい課題

紙の参考書・問題集で勉強していると、次のことが起きる。

- どこまで勉強したか分からなくなる
- 間違えた問題を後から見直したいが、どこだったか分からなくなる
- 紙に記録すると散らばる
- 本に直接大量に書き込みたくない
- 復習対象を別のノートで管理するのは面倒
- 借りた本だと書き込めない

**紙の教材はそのまま紙で使う。**「どこまでやったか」「どこを見直したいか」だけをスマホで管理する。

## 思想

> **何を勉強するかを AI が決めるのではなく、ユーザー自身が決める。その判断と管理を Revia が手助けする。**

Revia は「AI 家庭教師」ではない。「今日は問題 32〜45 をやりましょう」と一方的に指示するものにはしない。

ユーザーが「ここはもう一度やりたい」と思ったものに印を付け、それを後から簡単に確認できるようにする。**判断はユーザーがして、Revia は覚えておく係**。

### AI の位置づけ

**AI は意思決定者ではなく入力補助。**

```
教材の目次を撮影 → AI → 章・節などを構造化 → ユーザーが確認・修正 → 教材として登録
```

生成 AI を使うこと自体をアプリの価値にはしない。AI が効くのは**最初の登録負担を下げるところ**だけで、そこから先（状態の記録、復習の確認、メモ）は通常のアプリ処理で完結する。

この線引きには実務上の利点もある。**AI を呼ぶのが教材登録のときだけ**なので、API の費用が使用量に比例して膨らまない。

### 紙をデジタル化するアプリではない

問題そのものを撮影して保存する機能は作らない。30 問あるなら「問題 1〜30」を範囲指定で一括生成する。

**紙の教材と一緒に使うアプリ**であって、紙を置き換えるものではない。

## やらないこと

| やらないこと | 理由 |
|---|---|
| AI が学習内容を指示する | 思想に反する。判断はユーザーがする |
| 問題画像の大量保存 | 紙をデジタル化するアプリではない |
| 学習時間の記録 | 「何時間やったか」は「どこを見直したいか」を助けない |
| 進捗率をアプリの主役にする | 中心価値は「何 % 終わったか」ではない。集計は出すが、主役にはしない |
| 「AI」「分析」「おすすめ」をメインタブに置く | ナビゲーションは `教材` と `復習` の 2 つを中心にする |

## 競合との違い

学習管理アプリには次のような型がある。

- 学習時間を記録する
- 参考書の進捗を管理する
- 間違えた問題を保存する
- 問題写真を取り込んで復習する
- 問題番号だけを管理する

Revia は**目次を撮影して教材の構造を作り、紙の教材はそのまま使いながら、章・節・問題の単位で学習・復習の状態を管理する**ところに立つ。

特徴は**最初の登録負担の小ささ**にある。

| 登録するもの | やり方 |
|---|---|
| 章・節の構造 | 目次を撮影して AI が構造化し、ユーザーが直す |
| 問題 | 範囲指定（開始番号・終了番号）で一括生成 |

30 枚撮影したり 30 個手入力したりせずに、教材 1 冊が登録できる状態を目指す。

## 現在の位置づけ

**ポートフォリオとして作る**（2026-09-23 の判断）。ストアへの公開は、権利・規約の整理がついてから改めて判断する（調査は [ai-terms-research.md](ai-terms-research.md)）。

そのため次の前提で設計する。

- 使うのは開発者自身。**複数人での利用・同期・アカウントは作らない**
- AI の API は自分のキーで自分だけが使う。費用は自分持ち
- **公開リポジトリに実在の教材の目次（画像・テキスト・スクリーンショット）を入れない。** デモとテストには自作の架空の目次を使う

将来ストアに出す判断をしたときに詰まるのは、**クラウドの AI に他人の著作物を送ることを、多数のユーザーに提供する形で行ってよいか**という点。そのときに端末内 OCR へ切り替えられる作りにしておけば、機能ごと失わずに済む。
