# Revia のコンセプト

> 紙の参考書・問題集の目次を取り込み、どこまで学習したか・どこを見直したいかを自分で管理できる復習支援アプリ。

このアプリが**なぜ必要で、誰のためのもので、何をしないか**を書く。変わりにくいものを置く場所。

- 何をどう作るかは [design.md](design.md)
- 決定の経緯と理由は [decisions.md](decisions.md)
- 決める過程は Issue #5

## 解決したい課題

紙の参考書・問題集で「どこを見直すか」を管理する方法は、ふつう**本に直接 × や印を付ける**こと。**それができない、したくない場面がある。**

| 場面 | 何が起きるか |
|---|---|
| 本を汚したくない | 印を付けられない。見直す場所が本に残らない |
| 借りたテキスト・共用の教材 | そもそも書き込めない |
| ノートに書き出す | **どこに書いたか分からなくなる。** 本とノートを行き来する手間も増える |
| 印が増えすぎる | どれが本当に見直したい場所か分からなくなる |

課題は「復習すべきだと気づけない」ことではない。必要なのは、**本に書き込まずに、見直す場所を記録して、あとから探せるようにすること**。

## 紙との比較

**一番の競合は他のアプリではなく「紙に直接印を付けること」。** アプリを使わない選択肢に勝てなければ、使われない。

### 紙のほうが優れている点

正直に書く。ここを認めないと、勝てる場所を見誤る。

| | 紙 |
|---|---|
| 速さ | **印を付けるのが 1 秒。** 起動も検索も要らない |
| 前提 | 電池もアカウントも要らない |
| 一覧性 | ページを開けば周りの問題も同時に見える |
| 取り違えにくさ | **印と問題が同じ場所にある。** どの問題の印かを間違えようがない |

### Revia が勝てる点

| | Revia |
|---|---|
| 本を汚さない | **印が本の外に残る。** 借りた本・共用の教材でも使える |
| 見直す場所を絞れる | 「要復習」だけを一覧にできる。紙は印が増えると探せなくなる |
| 状態を後から変えられる | 消しゴムで消す必要がない。理解できたら外すだけ |
| 複数冊をまたげる | 今日見直すべき場所を、本をまたいで 1 つの画面で見られる |

**速さでは紙に勝てない**ので、そこで競わない。状態を変える操作を 1 タップに抑えるのは、**紙との差を詰めるため**であって、紙を超えるためではない。

## 誰のため

**使い手と、ポートフォリオの読み手は別。** 作るものの判断は前者、見せ方の判断は後者で決める。

| | 誰 | 何を求めているか |
|---|---|---|
| 使い手 | 紙の参考書・問題集で勉強していて、**本に書き込めない / 書き込みたくない**人。まずは開発者自身 | 本を汚さずに、見直す場所を記録して探せること |
| ポートフォリオの読み手 | 採用担当者・技術者 | **開発の進め方**と、**作ったアプリで使った技術・工夫**の両方 |

後者のために、決定の理由を [decisions.md](decisions.md) に、開発の過程を Issue と PR に残している。

## 思想

> **本に書き込む代わりになる。**

紙でやっていたこと——印を付ける、付箋を貼る、次にやるところを探す——を、**本を汚さずにできるようにする**。目指すのはそこまでで、紙でやっていなかったことまで引き受けない。

これが機能を足すかどうかの判断基準になる。

> **紙でやっていないことは、入れる前に理由が要る。**

学習時間の集計も、AI による提案も、他人との共有も、紙に印を付けているときにはやっていない。**入れるなら「なぜ紙のやり方を超える必要があるか」を先に説明する。**

### AI の位置づけ

この思想から、AI の使いどころが決まる。

紙なら**本そのものが目次**なので、何も取り込まなくていい。アプリにすると、**目次を取り込む手間が新しく生まれる**。紙には無かった負担なので、**AI はそこを埋めるために使う**。

```
目次を撮影 → AI が構造化 → ユーザーが確認・修正 → 登録
                                                    ↓
                            復習一覧で見直す ← 状態を変える
              └─ ここから先は AI を使わない ─┘
```

**AI は意思決定者ではなく入力補助。** 登録より後（状態の記録、復習の確認、メモ）は通常のアプリ処理で完結する。

運用上の利点もある。**AI を呼ぶのは教材登録のときだけ**なので、費用が使用量に比例して膨らまない。

## やらないこと

足すかどうか迷ったときの判断基準にする。

| やらないこと | 理由 |
|---|---|
| AI が学習内容を指示する | **判断はユーザーがする。** 「今日は問題 32〜45 をやりましょう」と決めるアプリにしない |
| 問題画像の保存 | **撮影は解析にだけ使い、保存しない。** 紙をデジタル化するアプリではない。他人の著作物を端末やサーバーに溜めないので、権利の露出も増えない |
| 学習時間の記録 | 「何時間やったか」は「どこを見直したいか」を助けない。学習管理アプリの定番だが、**この課題とはずれている** |
| 他人との共有・塾向けの管理 | **個人の道具に徹する。** 共有を入れるとアカウントと権限管理が要る |

**どれも「紙でやっていないこと」。** 思想の判断基準をそのまま当てている。
