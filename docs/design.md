# Revia の設計（MVP）

**何をどう作るか**を書く。実装の根拠にする場所。

- なぜ作るかは [concept.md](concept.md)
- なぜその形にしたかは [decisions.md](decisions.md)
- **ここに書かれていないことは決まっていない。** 実装の前に Issue で決める

## MVP の範囲

**一本道を先に通す。** 教材を 1 冊登録して、状態を記録して、復習一覧で見直すまで。

```
目次を撮影 → AI が構造化 → 確認・修正 → 登録
                                          ↓
                    復習一覧で見直す ← 状態を変える
```

| 機能 | MVP | 備考 |
|---|---|---|
| 教材一覧 | ✅ | 集計（学習済み / 要復習）を出す |
| 教材追加（目次を複数枚撮影） | ✅ | |
| AI による目次解析 | ✅ | **方式は Issue #6 で実測して決める**（下の「MVP の前提」） |
| 解析結果の確認・修正 | ✅ | **実質ツリー編集 UI。MVP で一番重い** |
| 問題番号の範囲一括生成 | ✅ | これが無いと問題の階層を作れない |
| 教材詳細（ツリー表示 ＋ 要復習の絞り込み） | ✅ | |
| 状態のクイック変更 | ✅ | 1 タップで循環。詳細画面を開かせない |
| 復習一覧（教材をまたぐ） | ✅ | |
| 手動での教材登録 | ⏭ 後回し | **ツリー編集 UI ができれば「空から始める」だけ**。AI が使えなくなったときの逃げ道は失われない |
| メモ | ⏭ 後回し | データモデルには列を持っておく |
| 進捗表示（バー・グラフ） | ⏭ 後回し | 教材一覧の**集計の数字は MVP に入る** |
| クラウド同期 | ⏭ 後回し | **作る方向**（ポートフォリオとして見せる対象）。**後から外せる作りにする** |
| 課金（Play Billing） | ⏭ 後回し | Play へ公開すると決めたときだけ。**🔴 高** |
| 学習時間の記録 | ❌ | [concept.md](concept.md)「やらないこと」 |
| 問題画像の保存 | ❌ | 同上。**撮影は解析にだけ使い、保存しない** |
| AI による学習指示・AI チャット | ❌ | 同上 |
| 他人との共有・塾向けの管理 | ❌ | 同上 |

### MVP の前提

**AI 解析を MVP に入れたので、Issue #6（読み取り方式の実測）が MVP の前提になった。** #6 が終わるまで、教材追加の画面は作り切れない。

実装の順番はこうする。**ツリー編集 UI を先に作れば、#6 の結果を待つ間も進む。**

| 順 | 作るもの | #6 に依存するか |
|---|---|---|
| 1 | データモデル（`materials` / `items`） | しない |
| 2 | 教材詳細（ツリー表示・状態の変更・絞り込み） | しない |
| 3 | 教材一覧（集計） | しない |
| 4 | 復習一覧 | しない |
| 5 | ツリー編集（空から作る＝手動登録） | しない |
| 6 | 教材追加（撮影 → AI 解析 → 確認・修正） | **する** |

5 まで終われば、**手で登録して一本道が通る**。6 はそこに AI での取り込みを足すだけになる。

## 画面

### ① 教材一覧

登録した教材を並べる。**集計は葉（子を持たない項目）だけを数える**（[decisions.md](decisions.md)）。

```
┌──────────────────────────┐
│ 教材                   [＋] │
├──────────────────────────┤
│ 基本情報技術者 午前対策     │
│ 学習済み 32 / 要復習 12    │
├──────────────────────────┤
│ TOEIC 文法問題集           │
│ 学習済み 8 / 要復習 3      │
└──────────────────────────┘
```

### ② 教材追加

複数の画面をまたぐ流れ。**途中で失敗しても、撮り直しから再開できる。**

```
撮影 → （複数枚）→ 解析中 → 確認・修正 → 登録
                      ↑          │
                      └── やり直す ┘
```

| 段階 | 何が起きるか |
|---|---|
| 撮影 | 目次のページを複数枚。**撮った画像は解析にだけ使い、保存しない** |
| 解析中 | AI が章・節・問題の階層を組み立てる。**4 段に正規化する**（[decisions.md](decisions.md)） |
| 確認・修正 | **実質ツリー編集 UI。** 見出しの追加・削除・改名・段の上げ下げ・並べ替え。問題番号の範囲一括生成もここ |
| 登録 | 教材として保存する |

**確認・修正を飛ばせない。** AI の解析は必ず間違うので、ユーザーが直す前提にする。

### ③ 教材詳細

教材 1 冊のツリー。**この画面で状態を変える**のが主な使い方。

```
┌──────────────────────────┐
│ ← 基本情報技術者            │
│ [すべて] [要復習だけ]        │
├──────────────────────────┤
│ ▼ 第1章 コンピュータ        │
│   ▼ 1.1 CPU               │
│       問題1               │
│       問題2          ✓    │
│       問題3          🔖   │
│   ▶ 1.2 メモリ        🔖   │
│ ▶ 第2章 ネットワーク        │
└──────────────────────────┘
```

- **右端をタップすると状態が循環する**（`空白 → ✓ → 🔖 → 空白`）。詳細画面を開かせない
- 状態は**全階層が持つ**。章にも節にも問題にも印が付く
- **4 段目以降は字下げを増やさない**（[decisions.md](decisions.md)）
- 「要復習だけ」の絞り込みが**本単位の入り口**

### ④ 復習一覧

**教材をまたいで**、要復習の項目を集める。**横断の入り口。**

```
┌──────────────────────────┐
│ 復習                      │
├──────────────────────────┤
│ 基本情報技術者  1.2 メモリ  🔖│
│ 基本情報技術者  問題12     🔖│
│ TOEIC 文法     2.2 時制    🔖│
└──────────────────────────┘
```

- **教材名を添える。** またぐ以上、どの本の話か分からないと探せない
- ここでも状態を変えられる。理解できたら付箋を外す

**入り口を 2 つ持つ理由**は、復習の始め方が 2 通りあるため。「この本を復習したい」と「復習したいから探す」。どちらが多いかは使い方で変わるので、**どちらも塞がない**。データは同じで、条件が 1 つ増えるだけなので安く済む。

### ナビゲーション

下部に `教材` と `復習` の 2 つ。**「AI」「分析」「おすすめ」をタブに置かない**（[concept.md](concept.md)「やらないこと」）。

## 状態モデル

**「結果」と「復習」はデータ上で分けて持つ。**

| 列 | 値 | 意味 |
|---|---|---|
| `result` | `unstarted` / `correct` / `wrong` | やったか、合っていたか |
| `needs_review` | 真偽 | もう一度やりたいか |

**この 2 つは本来別の概念。**

- 間違えたが、解説を読んで完全に理解した → `wrong` だが `needs_review` は false
- 正解したが、自信がなかった → `correct` でも `needs_review` は true

### UI は 1 タップの循環

データは分けるが、**画面では 3 つの状態を循環させるだけ**にする。**紙は印を付けるのが 1 秒**なので、操作量を増やすと紙に負ける（[concept.md](concept.md)「紙との比較」）。

| 表示 | 意味 | `result` | `needs_review` |
|---|---|---|---|
| **（空白）** | まだやっていない | `unstarted` | false |
| **`✓`** | やった | `correct` | false |
| **`🔖`（付箋）** | 見直したい | `wrong` | true |

**印は紙に合わせた**（[decisions.md](decisions.md)）。未着手は何も書かない、やったらチェック、見直したいところに付箋。`○` を未着手に使わないのは、**日本語圏では `○` が「正解」と読まれる**ため。`×` を使わないのは、**「正解したが自信がない」に使えなくなる**ため——データ上は `result` と `needs_review` を分けているのに、表示で「間違えた」に固定してしまう。

**データを分けて持つ理由**は、後から独立に操作する UI を足すときに、**データの移行が要らないから**。1 列で始めると移行が必要になり、それは [pr-risk-policy.md](pr-risk-policy.md) で 🔴 高に当たる領域。

### 色は補助にする

付箋の色を変えて見つけやすくするが、**色だけで区別できる作りにしない**。色覚特性のある人と、明るい屋外で判別できなくなる。**印で区別がつくうえに、色が助ける**形にする。

## データモデル

**階層は可変ツリーで持つ。** 教材によって `章→節→問題` `章→問題` `章→節→小節→問題` と段数が違うため、固定の段数にしない。

```
materials
  id            TEXT    PRIMARY KEY
  title         TEXT    NOT NULL
  created_at    INTEGER NOT NULL
  updated_at    INTEGER NOT NULL

items
  id            TEXT    PRIMARY KEY
  material_id   TEXT    NOT NULL  → materials.id
  parent_id     TEXT    NULL      → items.id（NULL なら最上位）
  kind          TEXT    NOT NULL  chapter | section | question
  label         TEXT    NOT NULL  "第1章 コンピュータ" / "1.1 CPU" / "問題12"
  order_index   INTEGER NOT NULL  同じ parent の中での並び順
  number        INTEGER NULL      問題番号の数値。MVP では書かない
  result        TEXT    NOT NULL  unstarted | correct | wrong
  needs_review  INTEGER NOT NULL  0 | 1
  note          TEXT    NULL      メモ。MVP では書かない
  created_at    INTEGER NOT NULL
  updated_at    INTEGER NOT NULL
```

| 列 | なぜ要るか |
|---|---|
| `parent_id` | 可変ツリー。**段数に制限を入れない**（[decisions.md](decisions.md)） |
| `kind` | 階層は `parent_id` だけで表せるが、**問題だけは範囲一括生成の対象になり、表示も変わる**ので区別が要る |
| `label` | 表示に使う文字列。問題番号の振られ方が教材ごとに違うので、**数値ではなく文字列で持つ**（[decisions.md](decisions.md)） |
| `order_index` | 並び順。**MVP の並べ替えはこれだけで足りる** |
| `number` | **MVP では書かないが列は持つ。** 後から並べ替えや範囲指定に使うとき、移行を要らなくするため |
| `note` | 同上。メモ機能を後から足すときに移行が要らない |

集計（教材一覧の「学習済み 32 / 要復習 12」）は**葉だけ**を数える。

```sql
SELECT COUNT(*) FROM items
WHERE material_id = ?
  AND id NOT IN (SELECT parent_id FROM items WHERE parent_id IS NOT NULL);
```

## 実装で気をつけること

- **移行（マイグレーション）の列追加は冪等に書く。** 他のリポジトリで「版を戻してから上げ直した端末で DB が開けなくなる」事故が起きている（[AGENTS.md](../AGENTS.md) §6）。`ALTER TABLE ADD COLUMN` を無条件に打たない
- **実在の教材の目次をリポジトリに入れない。** デモとテストには自作の架空の目次を使う。撮影画像・抽出したテキスト・スクリーンショットのすべて（[research/ai-terms.md](research/ai-terms.md)）
- **AI の解析結果は信用しない。** 確認・修正の画面を飛ばせる作りにしない
- **同期は後から外せる形にする。** Play へ公開すると決めたら端末内に落とす（[concept.md](concept.md)）
