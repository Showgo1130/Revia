# Revia の設計（MVP）

**何をどう作るか**を書く。実装の根拠にする場所。

- なぜ作るかは [concept.md](concept.md)
- なぜその形にしたかは [decisions.md](decisions.md)
- 見て触れる見本は [ui/index.html](ui/index.html)。**あれは挿絵で、値の正本はこのファイル**。食い違ったらこちらが正しい
- README に載せている画像は `ui/screenshot.png`。**見本から起こした生成物**なので、画面を変えたら [ui/screenshot.md](ui/screenshot.md) の手順で撮り直す
- **ここに書かれていないことは決まっていない。** 実装の前に Issue で決める

## MVP の範囲

**一本道を先に通す。** 教材を 1 冊登録して、状態を記録して、復習一覧で見直すまで。

```
目次を撮影 → AI が構造化 → 確認・修正 → 登録
                                          ↓
                    復習一覧で見直す ← 状態を変える
```

| 機能 | MVP | 備考 |
|---|---|---|
| 教材一覧 | ✅ | 集計（学習済み / 要復習）を出す |
| 教材追加（目次を複数枚撮影） | ✅ | |
| AI による目次解析 | ✅ | **方式は Issue #6 で実測して決める**（下の「MVP の前提」） |
| 解析結果の確認・修正 | ✅ | **実質ツリー編集 UI。MVP で一番重い** |
| 問題番号の範囲一括生成 | ✅ | これが無いと問題の階層を作れない |
| 教材詳細（章を畳むツリー ＋ 要復習の絞り込み） | ✅ | |
| 状態のクイック変更 | ✅ | 1 タップで循環。詳細画面を開かせない |
| 教材の編集（ツリー・タイトル） | ✅ | **登録前の「確認・修正」と同じ UI を使い回す** |
| 教材の削除 | ✅ | 無いと、試したデータが消せずに溜まる |
| 最後にやった日の記録 | ✅ | 下の「履歴」。判断は [decisions.md](decisions.md) 18 |
| 復習一覧（教材をまたぐ） | ✅ | |
| 進捗のバー | ✅ | **1 本の塗りとパーセントの文字だけ**。グラフは作らない（決定 25） |
| 手動での教材登録 | ✅ | **教材名の入力だけ足せば済む**。ツリー編集は MVP にあるため（決定 33） |
| 設定（読み取り回数・書き出し・テーマ・ライセンス） | ✅ | ライセンスは Lucide の ISC が要求する（決定 28） |
| メモ | ⏭ 後回し | **画面は設計済み**（画面 10）だが MVP では書かない。列は持つ |
| 項目の詳細画面 | ⏭ 後回し | MVP は一覧のタップだけで状態を変える。メモと同時に入れる |
| クラウド同期 | ⏭ 後回し | **作る方向**（ポートフォリオとして見せる対象）。**後から外せる作りにする** |
| 課金（Play Billing） | ⏭ 後回し | Play へ公開すると決めたときだけ。**🔴 高** |
| 間隔反復（いつ戻るかを自動で決める） | ❌ | 戻る時期はユーザーが見て決める。判断は [decisions.md](decisions.md) 18 |
| 学習時間の記録 | ❌ | [concept.md](concept.md)「やらないこと」 |
| 問題画像の保存 | ❌ | 同上。**撮影は解析にだけ使い、保存しない**（決定 30） |
| 本の表紙の写真 | ❌ | MVP では頭文字のタイルだけ（決定 26）。権利の整理が要るため後回し |
| AI による学習指示・AI チャット | ❌ | [concept.md](concept.md)「やらないこと」 |
| 他人との共有・塾向けの管理 | ❌ | 同上 |

### MVP の前提

**AI 解析を MVP に入れたので、Issue #6（読み取り方式の実測）が MVP の前提になった。** #6 が終わるまで、教材追加の画面は作り切れない。

実装の順番はこうする。**ツリー編集 UI を先に作れば、#6 の結果を待つ間も進む。**

| 順 | 作るもの | 画面 | #6 に依存するか |
|---|---|---|---|
| 1 | データモデル（`materials` / `items`） | — | しない |
| 2 | 見た目の基準（Compose のテーマ） | — | しない |
| 3 | 教材詳細（章の開閉・状態の変更・絞り込み） | 8 | しない |
| 4 | **ツリー編集**（詳細から開く。空から作れば手動登録になる） | 6 | しない |
| 5 | 教材一覧（集計・追加・削除）と手動登録 | 1・2・3・9 | しない |
| 6 | 復習一覧と絞り込み | 11・12・14 | しない |
| 7 | 設定 | 13 | しない |
| 8 | 教材追加（撮影 → AI 解析 → 確認・修正 → 完了） | 4・5・7 | **する** |

7 まで終われば、**手で登録して一本道が通る**。8 はそこに AI での取り込みを足すだけになる。

ツリー編集を早くに置いたのは、**登録後の編集にも同じ UI を使う**ため（[decisions.md](decisions.md) 17・33）。

## 見た目の基準

**ここが値の正本。** [ui/index.html](ui/index.html) はこの値を当てた見本で、食い違ったらこちらが正しい。

### 色

**彩度を持つのは要復習だけ**（決定 24）。ほかは無彩色に近い。

| 役割 | 値 | 使う場所 |
|---|---|---|
| 地 | `#F4F6FA` | 画面の背景 |
| カード | `#FFFFFF` | 教材・章・入力欄。**影を付けない**。内側に 1px の囲み `rgba(20,32,60,.10)` |
| 文字 | `#14161A` | 本文・見出し |
| 二次の文字 | `#6B7381` | 補助の文字・日付・件数・選んでいないタブ |
| 装飾の線 | `#A8AEB8` | 破線の円・矢印。**文字に使わない** |
| 朱 | `#BF4A2C` | **要復習の数字と ● の印だけ** |
| 墨 | `#2A2F38` | 進捗バーの塗り・主ボタン・解析中のチェック |
| ゲージの溝 | `#E2E7F0` | 進捗バーの背 |
| 罫 | `rgba(20,32,60,.10)` | 章の下・一覧の区切り。1px |
| 選択のカプセル | `rgba(20,32,60,.12)` | ナビの選択中 |
| チップの面 | `#E6EBF3` | 絞り込みチップ・頭文字のタイル |

**文字のコントラストは白の上で 4.5:1 以上**（決定 36）。実測値: 朱 5.0:1 ／ 二次の文字 4.8:1 ／ 文字 16.1:1。`#A8AEB8` は 2.2:1 なので文字に使わない。

**緑を足さない。** 完了は注意を引く必要がない状態なので、✓ は無彩色のまま（決定 24）。

### 寸法

画面幅 **360dp** を基準にする。

| もの | 値 |
|---|---|
| 画面の左右の余白 | 18dp（カードの外側は 12dp） |
| カードの角丸 | 12dp |
| ボタン | 高さ 46dp ／ 角丸 23dp |
| ナビ | 264 × 52dp ／ 角丸 26dp ／ 画面の下から 16dp |
| ナビの選択カプセル | **126 × 40dp** ／ 角丸 20dp ／ **0.34 秒でスライド**（決定 27） |
| 一覧の行 | 最小 34dp。字下げは 1 段ごとに 16dp、**4 段目以降は増やさない** |
| 印（未着手） | 直径 14dp ／ 破線 1.5dp ／ `#A8AEB8` |
| 印（済） | 12 × 7dp の折れ線 ／ 線 2dp ／ `#6B7381` |
| 印（要復習） | 直径 13dp の塗りつぶし ／ `#BF4A2C` |
| 印のタップ範囲 | **44dp 以上**（見た目と当たり判定を分ける） |
| 進捗バー | 高さ 6dp ／ 角丸いっぱい |
| 章の小バー | 30 × 4dp |
| 頭文字のタイル | **34 × 44dp** ／ 角丸 4dp。表紙の写真を入れるなら同じ枠（決定 26） |

### 書体

**Noto Sans JP** だけ使う。

| 用途 | 指定 |
|---|---|
| 画面のタイトル | Light 22sp ／ 字間 -0.02em |
| 画面名（小さいほう） | Medium 18sp |
| 本文 | Regular 12.5sp |
| 章の名前 | Medium 12sp |
| 補助の文字 | Regular 10〜11sp |
| ナビ | Regular 11sp（選択中は Bold） |
| 数字が並ぶ場所 | 等幅の数字（`font-variant-numeric: tabular-nums` 相当） |

### アイコン

**Lucide** を使う（決定 28）。SVG を Android Studio の Vector Asset でベクタードローアブルに変換して埋め込む。**ライブラリ依存は足さない。**

| 決まり | 値 |
|---|---|
| 線の太さ | **1.9**（既定の 2 は 18dp だと重い） |
| 大きさ | **18dp**（行内・ナビ）／ **20dp**（見出し・ボタン）の 2 つだけ |
| 色 | `currentColor`。**絵に色を持たせない** |
| ライセンス | **ISC**（Feather 由来）。著作権表示の保持が条件。設定に「ライセンス」の行を持つ |

使う 11 種。

`chevron-left`（戻る）／ `chevron-right`（章を開く・設定の行）／ `chevron-down`（選び直す）／ `plus`（足す）／ `x`（外す）／ `settings`（設定）／ `more-vertical`（メニュー）／ `trash-2`（削除）／ `grip-vertical`（並べ替えの取っ手）／ `camera`（撮る）／ `pencil`（手で作る）

**線引きは「意味が世界共通の操作は絵、このアプリ固有の概念は文字」**（決定 28）。「教材」「復習」「要復習」は文字のまま。

**印（○・✓・●）は Lucide にしない。** アプリの語彙そのもので、ライブラリの更新で見た目が変わる余地を作らない（決定 28）。

## 画面

**全 14 画面。** 見本は [ui/index.html](ui/index.html)。

### 1. 教材一覧（空） — MVP

初回起動と、全部削除した後。

- 中央に本の背を模した図（無彩色）、「まだ教材がありません」、目次を撮ると章と節が並ぶことの説明
- **ここだけ主ボタンを墨で塗る。** 他に何も無い画面なので、浮いたナビと競わない
- 教材が 1 冊でも入ったら、画面 2 の**破線の枠**に変わる

### 2. 教材一覧 — MVP

本棚。

- 見出しに「教材」、右に `settings`
- 冊数と、**教材をまたいだ要復習の合計**（朱）
- 各カード: **頭文字のタイル**（34 × 44dp）／ タイトル ／ `済 n / 全 m`・パーセント・`要復習 n`（朱）／ 進捗バー
- **要復習が 0 の教材には「要復習」の文字を出さない。** 朱がある＝やることがある、と読める状態にする
- 一覧の末尾に**破線の枠の「＋ 教材を追加」**。FAB にしない（浮くものを 2 つにしない。決定 27 と同じ理由）
- 長押しで並べ替え・改名・削除のメニュー（画面は持たない）

### 3. 追加方法の選択 — MVP

- 「目次を撮って作る」（`camera`・**おすすめ**の印）と「手で入力して作る」（`pencil`）の 2 つだけ
- 下に今月の読み取り回数。**上限を超えると手入力だけになる**ことを書く
- **両方いつでも使える。** 手入力は読み取りが失敗したときの逃げ道でもある

### 4. 目次の写真 — MVP（#6 に依存）

- **カメラ画面は持たない。** 端末の標準カメラに渡し、戻ってきた写真をここに並べる（決定 29）
- 撮った写真のサムネイル（`x` で外せる）＋ `camera` で追加
- 「目次のページが全部入るように。2〜3 枚に分けて構わない」
- **「写真は読み取りが終わると端末から消す」と画面に書く**（決定 30）

### 5. 解析中 — MVP（#6 に依存）

- ぐるぐる ＋ **見出しの文が進行に合わせて変わる**（文字を読み取っています → 章と節に組み立てています → 問題番号を拾っています）
- 3 段のステップ。**終わった段に ✓ が付く**（決定 28。一覧の「済」と同じ印・同じ弾み方）
- **見出しと ✓ の両方を動かす。** 見出しは目線の中心にあるので気づきやすく、✓ はどこまで進んだかが残る
- やめるボタン
- **未決: 読み取りを端末内でやるか外部の AI に送るか。** 送るならこの画面に明示が要る（Issue #6）

### 6. 読み取り結果の確認 — MVP

**このアプリで一番作り込む画面。** 読み取りは必ず間違うので、ここの出来が印象をほぼ決める。

- 読み取った章・節・問題のツリー。章の行に `grip-vertical` の取っ手
- **自信の低い行に「要確認」を付ける。** 直す場所を探させないため
- **「要確認」に朱を使わない**（決定 31）。墨の枠と点線。ここで朱を使うと ● の意味がぼやける
- 追加・削除・改名・段の上げ下げ・並べ替え。**問題番号の範囲一括生成もここ**
- 長押しで並べ替え、左右になぞって階層を変える
- **この画面を飛ばせる作りにしない**
- **画面 9（手で作る）から空の状態で開くのも同じ画面**（決定 33）

### 7. 登録完了 — MVP

- 大きな ✓（**墨**。緑にしない）、教材名、`全 n 章・m 項目`
- 「この教材を開く」（主ボタン）と「教材一覧に戻る」

### 8. 教材詳細 — MVP

教材 1 冊。**この画面で状態を変える**のが主な使い方。

- 見出し: `chevron-left` ／ パンくず「教材」／ `more-vertical`
- 教材名、`済 n / 全 m`・パーセント・`要復習 n`（朱）、進捗バー
- 絞り込みチップ「すべて」「要復習だけ」
- **章はカードに畳む**（決定 23）。閉じた章にも**要復習の数（朱の文字）と小さな進捗バー**が出るので、**開かずにどの章へ戻るか決められる**
- 章の見出しをタップで開閉。開いた章は白に起き、髪の毛ほどの囲みが付く
- 開いた章の中: 節と問題のツリー。右端の印をタップすると **未着手 → 済 → 要復習** と循環
- **日付はここに出さない**（決定 20）
- `more-vertical` から章の追加・改名・削除、タイトル変更、教材の削除。**削除は確認を挟む**
- **未決: 章の開閉状態を覚えるか**（最後に開いていた章だけ復元する案）

### 9. 手で作る（教材名） — MVP

- 教材の名前の入力
- 一覧での見え方（頭文字のタイルの見本）。**あとから表紙の写真に差し替えられる**と書く
- 「次へ」で**画面 6 を空の状態で開く**

### 10. 項目の詳細・メモ — ⏭ 後回し

**画面は設計済みだが MVP では作らない。** MVP は一覧のタップだけで状態を変える。

- 見出し: 戻る ／ パンくず（教材名・章）／ `more-vertical`、項目名
- 状態の選択（○・✓・● を横に 3 つ。**一覧と同じ印を使う**）
- メモ（500 字まで）
- **最後にやった日はここに出す**
- 前後の項目へ直接動ける。**1 問ごとに一覧へ戻らされるのは紙より不便**になるため
- `trash-2` ＋「この項目を削除」（**取り返しがつかないので言葉も残す**）

### 11. 復習一覧（空） — MVP

- ○ ● ○ の図、「要復習はありません」、「間違えた問題に ● を付けるとここに集まります」
- **全部終わった状態と何もしていない状態で文言を分けない。** どちらも「やることがない」のは同じ

### 12. 復習一覧 — MVP

**教材をまたいで**要復習を集める。**横断の入り口。**

- 見出し「復習」、件数、「要復習だけを集めています」
- **選択チップが 2 つ**: `すべての教材 ▾` と `古い順 ▾`（決定 34）。**今の値をチップに書く**
- 各行: 項目名 ／ 教材名・章（小さく）／ 最後にやった日 ／ ●
- **日付は無彩色**（決定 25）。朱にすると「そろそろやれ」という合図になり、**いつ戻るかを自動で決めない**という方針と擦れる
- **印に画面ごとの特例を作らない**（決定 35）。ここは ● が縦に並ぶが、それでよい
- ● をタップすると行が消える。**取り消しの案内を数秒出す**

### 13. 設定 — MVP

**タブにしない**（決定 32）。画面 1・2 の見出しの `settings` から入る。

| 群 | 行 |
|---|---|
| 読み取り | 今月の読み取り（n / m 回とゲージ）／ 読み取りの精度について |
| データ | バックアップを書き出す ／ バックアップから戻す ／ すべての教材を削除 |
| 表示 | テーマ（端末に合わせる / 明るい / 暗い） |
| このアプリについて | 使い方 ／ プライバシーポリシー ／ **ライセンス** ／ バージョン |

**ログインの項目は無い。** データは端末内で完結する前提（[concept.md](concept.md)）。同期を足すならここに増える。

### 14. 教材で絞る — MVP

画面 12 のチップをタップすると下から出るシート。

- 「すべての教材」＋ 各教材。**それぞれの要復習の件数を添える**
- 選んでいるものに ✓
- **要復習が 0 件の教材は出さない。** 選んでも何も出ない選択肢は選ばせない
- 並び順も同じ形のシート（古い順 ／ 教材の順 ／ 最近付けた順）

### ナビゲーション

下部に `教材` と `復習` の **2 つだけ**。浮いた半透明のカプセル（264 × 52dp）。

- **AI はタブにしない。** 入力補助であって機能の柱ではない（[concept.md](concept.md)「AI の位置づけ」）
- **設定もタブにしない**（決定 32）。ナビはよく行く場所のためのもの
- **選択中は半分の幅いっぱいのカプセル**（126 × 40dp、墨 12%）。**面・濃さ・太さの 3 つで差を付ける**ので、半透明ごしに背景が透けても読める（決定 27）
- **文字だけ。絵を入れない。**「復習」に定まった絵が無く、`rotate-ccw` は取り消しにも再読み込みにも使われる（決定 28）
- ぼかしは `RenderEffect`（API 31 以上）。**minSdk 26 では不透明に近い単色に落とす。** 形・影・浮きは残るので破綻しない

## 状態モデル

**「結果」と「復習」はデータ上で分けて持つ。**

| 列 | 値 | 意味 |
|---|---|---|
| `result` | `unstarted` / `correct` / `wrong` | やったか、合っていたか |
| `needs_review` | 真偽 | もう一度やりたいか |

**この 2 つは本来別の概念。**

- 間違えたが、解説を読んで完全に理解した → `wrong` だが `needs_review` は false
- 正解したが、自信がなかった → `correct` でも `needs_review` は true

### UI は 1 タップの循環

データは分けるが、**画面では 3 つの状態を循環させるだけ**にする。**紙は印を付けるのが 1 秒**なので、操作量を増やすと紙に負ける（[concept.md](concept.md)「紙との比較」）。

| 表示 | 意味 | `result` | `needs_review` |
|---|---|---|---|
| **薄い破線の円** | まだやっていない | `unstarted` | false |
| **`✓`** | やった | `correct` | false |
| **朱の塗りつぶした丸（●）** | 見直したい | `wrong` | true |

**印は紙に合わせてある。** 未着手は印を付けない（タップ領域を示す薄い破線の円だけ）、やったらチェック、見直したいところに付箋の代わりの丸。

**絵文字（`🔖`）は使わない**（決定 28）。端末ごとに絵が変わるうえ、置いた瞬間に安っぽくなる。`○` と `×` を使わない理由と、データを 2 列に分ける理由は [decisions.md](decisions.md) 11・12。

### 色は補助にする

**色だけで区別できる作りにしない。** 色覚特性のある人と、明るい屋外で判別できなくなる。**印で区別がつくうえに、色が助ける**形にする。3 つとも形が違う（破線の輪 ／ 折れ線 ／ 塗りつぶした円）。

**画面ごとに印の形や色を変えない**（決定 35）。○・✓・● はこのアプリの語彙そのもので、画面によって変わる語彙は覚えられない。

## 履歴（最後にやった日）

**「いつやったか」を記録する。** MVP では `items.last_done_at` の 1 列だけ持ち、**最後にやった日**が分かればよい。

| 使い道 | 中身 |
|---|---|
| 表示 | **復習一覧（画面 12）と項目の詳細（画面 10）にだけ**添える。教材詳細には出さない（[decisions.md](decisions.md) 20） |
| 並べ替え | 復習一覧を「しばらく見ていない順」に並べられる |

**何回やったかの履歴（別テーブル）は MVP では持たない。** 判断は [decisions.md](decisions.md) 18。

### 間隔反復（SRS）はやらない

「この項目は 3 日後に出す」とアルゴリズムが決める仕組みは作らない。**並べ替えは助けるが、順番を押し付けない**（[decisions.md](decisions.md) 18）。

**日付を強調しないのも同じ理由**（決定 25）。古い日付を朱にすると「そろそろやれ」という合図になる。

## データモデル

**階層は可変ツリーで持つ。** 教材によって `章→節→問題` `章→問題` `章→節→小節→問題` と段数が違うため、固定の段数にしない。

```
materials
  id            TEXT    PRIMARY KEY
  title         TEXT    NOT NULL
  created_at    INTEGER NOT NULL
  updated_at    INTEGER NOT NULL

items
  id            TEXT    PRIMARY KEY
  material_id   TEXT    NOT NULL  → materials.id
  parent_id     TEXT    NULL      → items.id（NULL なら最上位）
  kind          TEXT    NOT NULL  chapter | section | question
  label         TEXT    NOT NULL  "第1章 コンピュータ" / "1.1 CPU" / "問題12"
  order_index   INTEGER NOT NULL  同じ parent の中での並び順
  number        INTEGER NULL      問題番号の数値。MVP では書かない
  result        TEXT    NOT NULL  unstarted | correct | wrong
  needs_review  INTEGER NOT NULL  0 | 1
  last_done_at  INTEGER NULL      最後にやった日
  note          TEXT    NULL      メモ。MVP では書かない
  created_at    INTEGER NOT NULL
  updated_at    INTEGER NOT NULL
```

| 列 | なぜ要るか |
|---|---|
| `parent_id` | 可変ツリー。**段数に制限を入れない**（[decisions.md](decisions.md) 10） |
| `kind` | 階層は `parent_id` だけで表せるが、**問題だけは範囲一括生成の対象になり、表示も変わる**ので区別が要る |
| `label` | 表示に使う文字列。問題番号の振られ方が教材ごとに違うので、**数値ではなく文字列で持つ**（[decisions.md](decisions.md) 14） |
| `order_index` | 並び順。**MVP の並べ替えはこれだけで足りる** |
| `number` | **MVP では書かないが列は持つ。** 後から並べ替えや範囲指定に使うとき、移行を要らなくするため |
| `last_done_at` | **最後にやった日。** 復習一覧の並べ替えに使う。回数の履歴は持たない（上の「履歴」） |
| `note` | メモ。**MVP では書かないが列は持つ**（`number` と同じ理由） |

**教材の表紙の色やタイルの文字は持たない**（決定 26）。頭文字は `title` から取るだけなので、列を増やさない。表紙の写真を入れると決めたときに足す。

**教材を消すと `items` も消える**（`material_id` に外部キーと `ON DELETE CASCADE`）。ツリーの途中を消すと、その下の子も消える（`parent_id` も同様）。**どちらも削除の前に確認を挟む。**

集計（教材一覧の「済 32 / 100」「要復習 12」）は**葉だけ**を数える。

```sql
SELECT COUNT(*) FROM items
WHERE material_id = ?
  AND id NOT IN (SELECT parent_id FROM items WHERE parent_id IS NOT NULL);
```

**章の進捗バーも同じく、その章の下の葉だけを数える。**

## 実装で気をつけること

- **移行（マイグレーション）の列追加は冪等に書く。** 他のリポジトリで「版を戻してから上げ直した端末で DB が開けなくなる」事故が起きている（[AGENTS.md](../AGENTS.md)）。`ALTER TABLE ADD COLUMN` を無条件に打たない
- **実在の教材の目次をリポジトリに入れない。** デモとテストには自作の架空の目次を使う。撮影画像・抽出したテキスト・スクリーンショットのすべて（[research/ai-terms.md](research/ai-terms.md)）。**`docs/ui/index.html` も同じ**
- **AI の解析結果は信用しない。** 確認・修正の画面（6）を飛ばせる作りにしない
- **文字のコントラストを 4.5:1 より下げない**（決定 36）。薄くしたくなったら、色ではなく文字の大きさか配置で差を付ける
- **影を増やさない。** 影が付くのはナビだけ。カードに影を足すと、浮遊感がナビと分散する（決定 24）
- **`RenderEffect` のフォールバックを最初から入れる**（API 31 未満）。後付けにすると、落としたときに形まで崩れる
- **Lucide のライセンス表示を設定に入れる**（決定 28）。ISC は著作権表示の保持が条件。**入れる前に原文を確認する**
- **同期は後から外せる形にする。** Play へ公開すると決めたら端末内に落とす（[concept.md](concept.md)）
